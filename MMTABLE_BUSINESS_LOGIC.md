# MIndMapTable Business Logic

Этот документ фиксирует согласованную бизнес-логику приложения `MIndMapTable` по состоянию на текущие реализованные договорённости.

Документ нужен как рабочая спецификация поведения интерфейса, прежде всего для:
- таблиц;
- соединительных линий;
- выделения и групповых действий;
- копирования, вставки и дублирования;
- формул и пересчёта ссылок.

## 1. Общая модель рабочего стола

Приложение представляет собой бесконечный рабочий стол с объектами:
- фигуры;
- таблицы;
- заметки;
- линии;
- соединительные коннекторы;
- окна встроенных документов.

Каждый объект можно:
- выделять;
- перемещать;
- изменять по размеру;
- стилизовать через панель формата;
- сохранять в документ рабочего стола.

## 2. Выделение объектов

### 2.1. Одиночное выделение

При обычном клике выбирается один объект:
- фигура;
- таблица;
- соединитель;
- окно.

Если выбрана таблица, то возможны два режима:
- выделена сама таблица как объект;
- выделены ячейки таблицы.

### 2.2. Множественное выделение

Поддерживается множественное выделение:
- нескольких фигур;
- нескольких соединителей;
- фигур вместе с соединителями.

Способы:
- через `Shift/Ctrl/Cmd` по объектам;
- через рамку выделения.

### 2.3. Групповое перемещение

Если выделено несколько фигур, то при перетаскивании любой фигуры из выделения:
- двигаются все выделенные фигуры;
- двигаются все выделенные соединители;
- соединители, связанные с двигаемыми фигурами, не должны визуально оставаться на старом месте.

Если соединитель выбран вместе с фигурами:
- он должен перемещаться как часть общего блока;
- его маршрутные точки (`routePoints`) тоже должны сдвигаться вместе с блоком.

## 3. Соединительные линии

### 3.1. Создание

Соединители можно создавать между:
- фигурами;
- таблицами;
- ячейками таблиц;
- группами фигур.

### 3.2. Поведение соединителя

Соединитель может быть:
- прямой;
- ортогональный.

Соединитель хранит:
- начало;
- конец;
- стиль стрелок;
- толщину;
- цвет;
- маршрутные точки.

### 3.3. Поведение при перемещении объектов

Если соединитель привязан к объектам, то при перемещении объектов:
- концы соединителя должны следовать за объектами;
- линия должна перестраиваться корректно;
- если соединитель был выбран как отдельный объект в составе multi-select, он тоже должен участвовать в общем drag.

## 4. Таблицы

## 4.1. Таблица как объект

Таблица является отдельным объектом рабочего стола и поддерживает:
- перемещение;
- изменение размеров;
- стилизацию;
- заголовок;
- формулы в ячейках;
- связи с другими таблицами и фигурами.

## 4.2. Выделение в таблице

В таблице могут выделяться:
- одна ячейка;
- несколько ячеек;
- диапазон ячеек;
- строка через полное выделение её ячеек;
- столбец через полное выделение его ячеек;
- вся таблица как объект.

Если выделена одна ячейка, операции над строкой/столбцом должны трактовать её как контекст текущей строки и/или текущего столбца.

## 4.3. Высота строк

Высота строки может меняться только следующими способами:
1. ручным ресайзом строки курсором по границе строки;
2. изменением высоты через свойства таблицы/формат;
3. пропорциональным масштабированием при ресайзе всей таблицы зелёными угловыми хендлами.

Высота строки не должна самопроизвольно меняться:
- при нажатии `Enter` внутри ячейки;
- при редактировании текста;
- при вставке;
- при очистке;
- при прочих внутренних действиях в ячейке.

## 4.4. Ресайз таблицы зелёными и жёлтыми хендлами

### Зелёные угловые точки

При изменении размера таблицы зелёными угловыми хендлами:
- меняется размер всей таблицы;
- высоты строк масштабируются пропорционально;
- ширины столбцов масштабируются пропорционально.

### Жёлтые средние точки

При изменении размера таблицы жёлтыми боковыми хендлами:
- меняется внешний размер блока таблицы;
- строки и столбцы не должны пропорционально растягиваться;
- внутренние размеры треков должны сохраняться.

## 4.5. Ресайз строки курсором

Зона появления row-resize должна находиться:
- у реальной границы строки;
- не в середине ячейки;
- с приоритетом точного попадания по верхней/нижней границе строки.

## 4.6. Перемещение строк

Поддерживается ручное перемещение строк:
- drag за левую ручку строки;
- через кнопки `↑ Строка` и `↓ Строка`;
- через контекстные действия перемещения.

Правила:
- если выбрана одна ячейка, команды `↑ Строка` / `↓ Строка` двигают строку этой ячейки;
- если выбрано несколько строк, двигается весь блок строк;
- после перемещения выделение должно оставаться на перемещённом блоке.

## 4.7. Добавление строк

Кнопка `+ Строка` и нижний `+` у таблицы должны добавлять строку:
- не всегда в конец;
- а сразу под текущей выбранной строкой;
- если выделено несколько строк, новая строка добавляется после последней выбранной строки.

Если контекста выделения нет:
- строка добавляется в конец таблицы.

## 4.8. Добавление столбцов

Кнопка `+ Столбец` и правый `+` у таблицы должны добавлять столбец:
- сразу после текущего выбранного столбца;
- если выделено несколько столбцов, после крайнего правого выбранного столбца.

Если контекста выделения нет:
- столбец добавляется в конец таблицы.

## 4.9. Удаление строк

Кнопка `- Строка` должна удалять:
- строку активной ячейки, если выбрана одна ячейка;
- все строки, попавшие в текущее выделение, если выбрано несколько ячеек в нескольких строках;
- выбранный блок строк, если строка/строки выделены целиком.

Удаляться должны именно выбранные строки, а не последняя строка таблицы.

## 4.10. Удаление столбцов

Кнопка `- Столбец` должна удалять:
- столбец активной ячейки, если выбрана одна ячейка;
- все столбцы, попавшие в текущее выделение, если выбрано несколько ячеек в нескольких столбцах;
- выбранный блок столбцов, если столбцы выделены целиком.

Удаляться должны именно выбранные столбцы, а не последний столбец таблицы.

## 4.11. Внешний вид панели формата для ячеек

При выборе ячейки панель формата должна показывать реальные стили ячейки, а не сырые theme-переменные.

Правила:
- `Заливка` по умолчанию должна отображаться как белая, если фактическая заливка белая;
- `Градиент` по умолчанию должен отображаться как белый, если фактический цвет белый;
- `Линия` должна показывать фактический цвет контура ячейки;
- если фактический контур серый, в панели должен отображаться именно серый, а не чёрный.

## 5. Формулы в таблицах

## 5.1. Базовый синтаксис

Поддерживаются:
- обычные адреса ячеек, например `B2`;
- диапазоны, например `B2:B5`;
- ссылки на ячейки конкретной таблицы, например `Выручка_B2`;
- ссылки на фигуры, например `@shape_6`.

## 5.2. Пересчёт при вставке и удалении строк/столбцов

При добавлении, удалении и перемещении строк/столбцов:
- ссылки в формулах должны пересчитываться;
- должны корректироваться как внутренние ссылки таблицы, так и внешние ссылки из других таблиц на изменённую таблицу.

Это относится к:
- `B2`;
- диапазонам;
- токенам вида `НазваниеТаблицы_B2`.

## 5.3. Перемещение строк и бизнес-смысл формул

При перестановке строк:
- формулы должны сохранять логическую корректность;
- ссылки на строки изменённой таблицы должны ремапиться так, чтобы зависимые таблицы не продолжали смотреть в старые адреса.

Если строка в таблице была перемещена:
- связанные формулы в других таблицах должны обновиться на новый адрес той же логической строки.

## 6. Копирование, вставка и дублирование

## 6.1. Копирование фигур

При `Ctrl/Cmd+C` в буфер должны попадать:
- выбранные фигуры;
- выбранные таблицы;
- выбранные заметки;
- выбранные линии;
- выбранные соединительные коннекторы.

## 6.2. Вставка и дублирование

При `Ctrl/Cmd+V` и `Ctrl/Cmd+D`:
- должны создаваться новые копии объектов;
- вставка должна происходить со смещением;
- дублирование должно использовать ту же логику, что и копирование + вставка.

## 6.3. Вставка групп объектов с соединителями

Если в выделении были фигуры и соединительные линии между ними:
- при вставке группа должна восстанавливаться полностью;
- линии тоже должны создаваться заново;
- линии должны соединять новые копии объектов, а не старые исходные объекты.

Если линия соединяла выбранные фигуры:
- после вставки она должна соединять аналоги этих фигур в новой вставленной группе.

Если в старом буфере обмена нет данных о коннекторах:
- вставка старого формата всё равно должна продолжать работать.

## 6.4. Дублирование и копирование таблиц с уникальным именем

Таблицы участвуют в формулах через своё имя:
- имя таблицы является частью адресации, например `Выручка_B2`;
- поэтому две таблицы с одинаковым именем недопустимы для корректной логики ссылок.

При `Ctrl/Cmd+D` и при вставке скопированной таблицы:
- новая копия таблицы не должна сохранять исходное имя;
- новая таблица должна автоматически получать уникальное имя;
- имя формируется из исходного имени с суффиксом через нижнее подчёркивание.

Примеры:
- `Выручка` -> `Выручка_1`;
- следующая копия -> `Выручка_2`;
- `Расход` -> `Расход_1`, затем `Расход_2`.

Если дублируется таблица, у которой уже есть числовой суффикс:
- нумерация всё равно должна продолжаться по общей серии имени;
- не должно возникать двух одинаковых имён.

Правила для формул:
- формулы в старых, уже существующих объектах меняться не должны;
- формулы в новых копиях должны быть переписаны на новое имя новой таблицы;
- если копируется несколько связанных таблиц, то внутренние ссылки между новыми копиями тоже должны быть переназначены на новые имена этих копий;
- старая группа таблиц и её формулы должны остаться без изменений.

## 7. Группы фигур

Поддерживается логическое объединение фигур в группу.

Для группы:
- фигуры можно выбирать вместе;
- группа может иметь общий внешний selection box;
- внешние соединители могут подключаться к группе;
- при перемещении группы должны корректно перестраиваться соединения.

## 8. Что считать эталонным поведением

Если возникает конфликт между старым поведением и этим документом, эталонным считается:
- явное согласованное поведение из этого файла;
- затем текущее фактически реализованное поведение в `app.js`;
- затем визуальная проверка на локалке и на проде.

## 9. Приоритет дальнейших доработок

При любых будущих изменениях сначала нужно сохранять корректность:
1. таблиц и формул;
2. выделения и групповых действий;
3. соединителей;
4. копирования/вставки/дублирования;
5. синхронизации панели формата с фактическим состоянием объекта.
