# AGENTS for Table Workspace / MIndMapTable

Это приложение:
- `Table Workspace`
- локальное имя репозитория: `MIndMapTable`

## Что это

Интерактивный рабочий стол с окнами таблиц:
- drag/resize окон
- zoom рабочего стола
- документная модель рабочего стола
- автосохранение в текущий документ
- меню `Файл`: создать, открыть, удалить, копировать
- авторизация по email и паролю
- сохранение документов в SQLite по пользователю

## Прод

Приложение опубликовано в проде здесь:
- `https://mmtable.skitovich.ru`
- серверный IP: `95.163.226.145`

Хостинг и инфраструктура:
- REG Cloud

## Как получить доступ

SSH-доступ к серверу выполняется по ключу:
- `lumalms_deploy`

Практически это означает:
- подключаться по SSH к серверу `95.163.226.145`
- использовать приватный ключ `lumalms_deploy`
- если нужен пользователь на сервере, брать тот, который уже настроен в окружении деплоя

## Как устроены локалка и прод

- Локальный запуск: `python3 server.py` на `127.0.0.1:4173`
- Прод: `gunicorn` на сервере за nginx, внешний вход через `https://mmtable.skitovich.ru`
- Локально документы для гостя могут писаться в `workspace_documents/local_at_localhost/`
- На проде документы пишутся в `workspace_documents/<email_safe>/`
- На проде первый рабочий аккаунт: `skitovich@yandex.ru`
- Не путать локальное состояние браузера и серверные данные: продовые документы нужно проверять через серверный `workspace.db` и `workspace_documents`
- Если меняется хранение документов или авторизация, сначала проверять на локалке, затем переносить на прод

## Что учитывать при работе

- Не ломать прод-конфиг без необходимости.
- Если меняется публичное поведение приложения, сначала проверять локально, затем на проде.
- Для сетевых проверок считать домен главным публичным адресом, а IP использовать как технический ориентир.
